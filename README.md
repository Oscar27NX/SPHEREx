# SPHEREx sky explorer

Run from this directory with Python 3.11 or newer:

```powershell
python -m pip install -r requirements.txt
python server.py --precache
python server.py
```

Open http://127.0.0.1:8080. The server starts warming the five presets automatically; `--precache` waits for them and writes `.cache/precache-report.json`. The SQLite database and compact FITS cutouts are stored in `.cache/archive.sqlite3`, survive restarts, and are excluded from Git. Copy this directory with the application when transferring a prepared demo. `SPHEREX_CACHE_DIR` changes the cache location; `SPHEREX_PORT` changes the local port.

The preset menu contains Barnard's Star, Epsilon Indi B, WISE 0855, RW Aurigae, and R Draconis. Positions were resolved through CDS Sesame/SIMBAD on 2026-11-14. Barnard's epoch-2000 position is propagated to 2026.0 using its published proper motion, parallax, and radial velocity. WISE 0855 uses a 600-arcsecond field to include its displacement from the catalog position. Other presets use 300 arcseconds. The stored positions, provenance, and preset field sizes are in `releases.json`.

## Live data and cache behavior

The backend discovers current SPHEREx spectral-image collections from `https://irsa.ipac.caltech.edu/SIA?MAXREC=0`. It includes advertised wide and deep collections, rather than inventing release dates or hard-coding retired releases. The default `auto` selection searches all currently advertised spectral-image releases. The release selector can restrict that search. The refresh button updates release discovery.

SIA queries constrain position and observation time. The FOV is the full width of the square display in **arcseconds**. SIA discovers exposures containing its center. Native IBE cutouts use shared 600/1200/2400-arcsecond size buckets (with diagonal padding); each requested FOV has its own WCS projection and cache key. This lets nearby FOV choices reuse the downloaded FITS data. The requested time window ends at the current UTC time. The timeline brush selects among actual returned observing dates; the epoch dots are hidden without disabling the brush. `?ra=...&dec=...&fov=...&window=...` URLs work, and Share URL includes display settings.

For a responsive preview, the backend selects the earliest and latest available exposure per detector, preferring footprints containing the field center, after deduplicating reprocessed exposures. Exposures that only intersect the outer field are not included; the preview is not a complete mosaic. This is at most 12 cutouts, **not every exposure or a complete 102-channel spectrum**. The response records selection, collection names, observation dates, original access URLs, and any missing downloads. Small IBE cutouts are reprojected with their celestial WCS, including SIP distortion, onto a common north-up, east-left 64×64 grid. Nearest-neighbor sampling preserves the preview's measured surface-brightness values; this display is not a flux-conserving scientific mosaic.

SIA discovery and rendered previews expire after one hour. Expired previews remain visible while the backend refreshes them; new fields show a loading state. `SPHEREX_CACHE_TTL` changes the preview TTL in seconds. Failed refreshes preserve cached results and retry after a short backoff. Catalog queries use IRSA's Gator service for Gaia DR3 and AllWISE and are cached for a day. Successful versioned cutouts remain cached. Missing coverage, archive errors, and catalog errors are explicit; generated images or catalog records are never substituted.

Warm local cache latency is distinct from first-download latency. Uncached network requests cannot be guaranteed below 100 ms. IRSA also documents a delay between ingestion and SIA availability, so the application can only discover data already exposed by that service.

The browser immediately derives a labeled FOV preview from cached observations at the same coordinates, preserving measured pixel values and leaving uncovered areas blank. It filters releases and dates, rescales catalog markers, and never stores this approximate preview as an authoritative cutout. The backend provides the same fallback to clients without a browser cache and holds 24 recent sky responses in memory. Discovery queries are shared across FOV changes for one hour; changing the advertised collection list changes their cache key. Browser decoding and display stretch calculations are also reused. Full refinement continues in the background. A failed release change preserves the available view, explains the delay, and retries; upstream HTTP errors are not displayed verbatim.

Uncached requests show retrieval stages, elapsed time and actual completed/total image requests. Discovery and queue stages use an indeterminate progress bar. When SIA returns no images, the response immediately says “No data found” without waiting for catalog downloads. Network failures remain distinct from an empty result, and navigation to cached presets stays available while retrieval runs.

## Scientific display conventions

- SPHEREx `IMAGE` values are **MJy/sr**, not micrometers. Wavelengths and bandwidths come from the FITS spectral WCS and are in **µm**. The wavelength lookup uses detector pixels without reapplying the celestial SIP distortion.
- The spectrum panel shows actual center-pixel observations with their dates and wavelengths. Clicking the image samples that displayed pixel across the downloaded observations. If that pixel has no valid observations, the panel explicitly switches to a **field mean** of valid pixels, with the corresponding mean wavelengths. This fallback is not center-pixel photometry and is not used for FFT filtering. If the entire field is unavailable, explanatory messages replace empty image and chart panels. These previews are not proper-motion tracking, source photometry, a simultaneous SED, or an inferred 102-band spectrum.
- A spectral FFT needs uniformly spaced wavelength samples. For spacing `Δλ` in µm and `N` samples, frequency is `k/(N Δλ)` cycles/µm; its reciprocal is a **spectral period** in µm. DC has no finite period. `3e8/k` is invalid for FFT bin indices. Even for electromagnetic frequency in Hz, `c/f` is in meters and needs a factor of `1e6` for µm.
- `compute_spectral_fft` rejects irregular, duplicate, or missing wavelengths. The browser checks the same sampling requirement and requires at least four samples. For this small preview it evaluates the DFT directly and reconstructs low/mid/high components from disjoint thirds of the Fourier modes; their sum recovers the original brightness samples. Live sparse cutouts show detector coverage and an explanation, with unsupported filters disabled. No interpolation across missing channels is performed. Amplitude is `abs(FFT)`, not power.
- Available-array and Mean views average finite samples, with no zeros substituted for missing detectors. These are mixed-wavelength visualization composites, not claimed SNR-optimal coadds. RGB combines D5/D3/D1 into red/green/blue in Mean mode. A missing required detector triggers a labeled grayscale view of available data; individual pixels with incomplete RGB coverage also use labeled grayscale. Fully missing pixels remain transparent. Invert complements the display stretch and leaves measured values and masks unchanged. Spatial smoothing is a display-only local mean.
- Selecting RGB preserves Blink/Mean/Diff mode. **RGB + Blink** selects the nearest active observation separately for D5, D3 and D1 at the timeline cursor. Their measured planes become red, green and blue. Channel dates and their time span are visible; the tooltip includes release and MJD provenance. The display explicitly says **non-simultaneous**. No temporal interpolation or invented channels are used. The time brush and skipped epochs constrain all three selections. Equal-distance ties use the earlier exposure. **RGB + Mean** averages the selected observations per channel instead. Playback continues; with only two cached exposures per detector, several cursor dates can legitimately share the same RGB combination.
- RGB is a false-color visualization with independent channel stretches, not simultaneous photometry, a calibrated color ratio, or a motion measurement. Different observation dates, local wavelengths and PSFs can create color fringes. If a required detector is absent from the selected observations, the viewer labels its grayscale fallback; individual incomplete pixels remain grayscale and fully missing pixels remain transparent.
- Diff requires a single detector and at least two observations. It compares positive/negative means only where all selected center wavelengths differ by at most one quarter of the smaller local bandwidth. Other pixels remain blank. This is a conservative visualization check, not exact bandpass or PSF matching for scientific variability measurements.
- Gaia circles are projected into the image WCS after an approximate proper-motion propagation to the frame's date, or to the midpoint of the contributing time span for a composite. Lines connect the reference and estimated positions. Sources without proper motion remain at their reference positions. This PM-only estimate omits parallax, radial velocity, perspective acceleration and positional uncertainty; it is a visual aid, not a confirmed source association. AllWISE diamonds retain their reference positions. Overlay labels explain these differences, and clicking a visible marker identifies its catalog entry. Only returned catalog sources can be shown; catalog overlays are not complete cross-matches to image detections.
- Quality-flag outlines and hover readouts use the same contributing frames: the current frame for single-channel Blink, the three chosen exposures for RGB Blink, or the selected contributors for Mean. RGB Gaia markers use the midpoint of the contributing observation dates and are labeled accordingly. Image and overlay share the same zoom transform. Fourier controls filter the brightness spectrum, not the spatial image or catalog positions.
- Aladin 3.8.2 loads on demand from a local, pinned distribution. Survey tiles still require an external archive. AllWISE uses IRSA's published HiPS mirror of `P/allWISE/color`; the CDS endpoints returned errors during verification. The core viewer uses local D3 and cached archive data, so external font or Aladin loading cannot block it.
- Aladin retains the user's survey zoom across coordinate/FOV updates. Survey zoom is separate from the SPHEREx science FOV and does not trigger an image query.

## Verification

To showcase the Fourier controls, click **FFT demo**, or open `/?demo=fft`. The chart is explicitly labeled **synthetic, not sky measurements**, and uses 48 uniformly spaced samples with known low/mid/high components. Select each filter to isolate its component; click FFT demo again to return to observations. The synthetic signal never replaces image data or enters the archive cache. No currently verified preset supplies a valid ordinary spectral FFT from the sparse observed cutouts.

```powershell
python -m unittest discover -s tests -v
node --test tests/frontend.test.cjs
node --check app.js
```

Backend tests cover physical FFT periods, rejected inputs, future release discovery, explicit archive errors, RA-wrap footprints, WCS/FOV geometry, pixel/flag reprojection, spectral SIP handling, persistent caches, and concurrent refreshes. JavaScript tests cover request races, missing detectors, wavelength-safe differences, and share URLs.

`tests/browser.cjs` exercises the actual UI in headless Edge using a captured archive response as a fixture. It needs Playwright in `.cache/browser/node_modules`, a running server on port 8081, and `.cache/browser-fixture.json` containing an `/api/state` response. `BROWSER_PATH` can specify another Chromium executable. Its routed responses test UI behavior independently of archive availability; real cache contents are verified separately by `--precache`.

`node tests/live-browser.cjs` uses the real local API and all five cached presets, checks that every FOV change displays synchronously, and measures click-to-paint latency. It writes `.cache/latency-report.json` and `.cache/latency-preview.png`. See [the six-point verification report](guides/verification-2026-11-15.md) for measured results, regression coverage, and data limitations.

`node tests/sprint-browser.cjs` verifies RGB playback across subsequent queries, the moving timeline cursor, Gaia epoch motion, WISE alignment across FOV/zoom/mode/brush changes, the public FFT demo and its share URL, and uncached progress through an empty result. Astrometry fixtures in `tests/astrometry-fixture.json` were generated with `SkyCoord.apply_space_motion` and the backend's `display_wcs` at the equator, RA wrap and near the pole. See [the final sprint report](guides/final-sprint-verification.md).

`node tests/rgb-browser.cjs` checks an entire RGB playback cycle on each real cached target. It asserts actual unequal RGB pixel values, changing composite images, continued playback, and non-simultaneous provenance labels. See [the RGB verification report](guides/rgb-verification.md) for the before/after measurements and the interpretation of these colors.
